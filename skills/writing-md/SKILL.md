# writing-md — md для модели, а не для читателя

Документ для модели оценивается одним: сработает ли правило в нужный момент. Полнота и «на всякий случай» этому мешают.

Три факта, из которых следует всё остальное:
- Контекст — общий ресурс: «The context window is a public good».
- Раздутый файл не строгий, а слабый: «Bloated CLAUDE.md files cause Claude to ignore your actual instructions!» Правило есть, а модель его не соблюдает — файл длинный, и правило потерялось.
- **Модели нового поколения нужно меньше предписаний, чем прошлого.** Гайды Anthropic для поколения 5: «Skills developed for prior models are often too prescriptive… and can degrade output quality». Инструкция, написанная под модель двухлетней давности, сегодня снижает качество, а не страхует его.

## 1. Форма: цель, причина, границы, критерий

Пиши задачу и **причину одной строкой** — модель обобщает от объяснения лучше, чем от предписания («Claude is smart enough to generalize from the explanation»). Экономить надо на нарративе-истории «как я до этого додумался», а не на intent.

Дальше — границы («что НЕ делать» явным списком) и критерий готовности, по которому результат можно проверить машиной.

Пошаговый порядок прописывай только там, где шаг **хрупкий или необратимый**: миграции, точные команды, деструктив данных. Для остального цель бьёт инструкцию: «Prefer general instructions over prescriptive steps». Перечислять каждое нежелательное поведение по имени не нужно — короткая инструкция даёт тот же эффект, что список из десяти запретов.

Показывай образец желаемого вместо запрета: позитивный пример работает лучше, чем «не делай X».

Гейт пишется четвёркой: **какая ошибка · когда обязателен · какое свидетельство закрывает · кто решает**. Гейт без ошибки — ритуал, без свидетельства — уговор, без «кто решает» — владелец становится ОТК.

## 2. Жанр решает лимит

| Жанр | Где живёт | Лимит | Обязательное |
|---|---|---|---|
| **SKILL.md** | `skills/<имя>/SKILL.md` | **≤500 строк** (правило Anthropic), тело <5k токенов | `description` с условием срабатывания |
| **CLAUDE.md** | корень репо / `~/.claude/` | ≤200 строк, ≤1400 слов | только то, что применимо ВСЕГДА |
| **rules/*.md** | `.claude/rules/` | ≤100 строк | доменные инварианты, без процедур |
| **agents/*.md** | `~/.claude/agents/` | ≤120 строк | `description` + явные `model`/`effort` |
| **спека** | `docs/specs/` | ≤60 строк | Цель · Scope/Out-of-scope · Решения · **Проверяемые критерии** · Риски |
| **task packet** | в промпте агента | ≤40 строк | файлы · точные изменения · definition of done |
| **карточка фабрики** | `factory/backlog/` | ≤40 строк | frontmatter + DoD 3–7 **исполняемых команд** |
| **память** | `projects/*/memory/` | ≤30 строк | один файл = один факт |
| **vault permanent** | `Obsidian Vault/permanent/` | ≤30 строк | Правило · Почему · Как применять |
| **доки проекта** | `docs/` | ≤300 строк | штамп «Обновлено: YYYY-MM-DD» |

**Происхождение цифр честно:** Anthropic подтверждает только ≤500 строк для SKILL.md и «короче = выше adherence» для CLAUDE.md. Остальные лимиты — наши эвристики из замера собственной среды 27.07: жанры с записанным лимитом держатся около 300 слов, жанры без лимита разнесло до 9144. Работают, но это наш опыт, а не правило вендора.

Файл упёрся в лимит → выносить детали в `references/` на один уровень вглубь, а не поднимать лимит.

## 3. Где живёт правило

Одно правило = одно место: «if two rules contradict each other, Claude may pick one arbitrarily».

- Применимо к КАЖДОЙ задаче, одна строка → **CLAUDE.md**.
- Доменный инвариант (SQL, тесты, фронт) → **скилл с триггером в `description`**, не в `~/.claude/rules/`: глобальный rules/ инжектится в каждую сессию независимо от задачи. Инвариант, нужный только внутри одного репозитория, — в его `.claude/rules/`. Замер 31.07 (arXiv:2607.19257): набор из 80 постоянных правил исполняется идеально в ~0% прогонов у всех пяти моделей, из 40 — в 9–31%, из 10 — в 59–94%; позиция инструкции даёт ±8.7 п.п., решает объём.
- Процедура, многошаговый воркфлоу, «иногда» → **скилл**: «Instructions that are procedural belong in a skill rather than in CLAUDE.md».
- Факт о проекте или предпочтение владельца → **auto-memory**.
- Кросс-проектный урок с «почему» → **vault permanent** (через `/wrap`).
- Срабатывает только на определённых файлах → frontmatter `paths:`.

Правило уже есть в другом слое → обнови там, копия хуже отсутствия.

## 4. frontmatter и description

Поля SKILL.md: `name`, `description`, `when_to_use`, `allowed-tools`, `disallowed-tools`, `disable-model-invocation`, `user-invocable`, `model`, `effort`, `context`, `paths`, `argument-hint`, `hooks`, `shell`. Неизвестное поле игнорируется молча — сверься со списком, прежде чем изобретать новое.

`description` — единственное, по чему модель выбирает скилл среди сотни. Пиши **что делает + когда звать**, третьим лицом, ключевой кейс первым (`description` + `when_to_use` обрезаются на 1536 символов), и добавь «НЕ применять к …» — это отсекает ложные срабатывания.

Образец: `Extract text and tables from PDF files, fill forms, merge documents. Use when working with PDF files or when the user mentions PDFs, forms, or document extraction.`

⚠️ **Двоеточие в значении закавычивай.** `description: … НЕ для: README` не парсится как YAML: Claude Code стерпит и скилл будет виден, спека и валидатор Anthropic отвалятся. На этом споткнулся первый черновик данного скилла и ещё пять скиллов среды.

## 5. Чего не писать

Формулировки, которые на моделях нового поколения активно вредят:

- **«Перепроверь», «убедись»** словами — удалять, не переписывать: «instructions like these cause over-verification… removing them reduces wasted tokens **with no loss in quality**». Проверка остаётся, но висит на скрипте, хуке или команде прогона в DoD, а не на уговорах.
- **«Объясни ход мысли», «покажи рассуждения в ответе»** — на Opus 5.5 и Sonnet 5.5 триггерит refusal-категорию `reasoning_extraction` и роняет прогон.
- **«В сомнении — используй X», «по умолчанию зови Y»** — вызывает overtriggering: «Tools that undertriggered in previous models are likely to trigger appropriately now». Заменяй условием «когда происходит вот это».
- **«Сообщай только критичное», «будь консервативен»** в ревью-промптах — модель поймёт буквально и урежет находки. Проси полноту, фильтруй отдельным проходом.
- Много вариантов вместо одного дефолта, вложенные ссылки файл→файл→файл, `@путь` (форс-грузит файл в контекст), магические числа без причины.
- Литералы `$` + цифра и `$ARGUMENTS` в теле SKILL.md: при вызове с аргументами Claude Code подставляет в них слова аргументов (02.09 правило asyncpg читалось как «параметры `прогон, после`») — писать словами (`$N`, «доллар-номер»).

## 6. Проверка перед сохранением

```bash
python3 ~/.claude/skills/writing-md/check_md.py <файл> [<файл> ...]
```

Лимиты жанра, frontmatter и неизвестные поля, YAML-валидность, длина и лицо `description`, битые пути, вложенность ссылок. Exit 1 = чинить.

Второе мнение по frontmatter — валидатор Anthropic: `python3 ~/.claude/plugins/cache/claude-plugins-official/skill-creator/unknown/skills/skill-creator/scripts/quick_validate.py <папка скилла>`.

## 7. Жизненный цикл

Смена поколения модели — повод пересмотреть все инструкции: каждая кодирует допущение «модель сама не может», и допущения устаревают. Метод вендора дословно: «Review and consider removing older instructions **if default performance is better**» — снимать по одной и смотреть на результат, а не выбрасывать пачкой.

Модель игнорирует правило → сначала сократи файл, потом усиливай формулировку.

Правил становится больше — общая длина не растёт: новое вытесняет старое или уточняет его на месте.

⚠️ **Правила про верификацию зависят от модели цикла.** Раздел «Модели» Skill `harness` — один дом этого правила.
