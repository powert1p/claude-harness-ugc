## 2. Разбор локальных

**skill-creator** — метод «эмпирика вместо мнения»: черновик → 2–3 реалистичных теста → параллельные прогоны с скиллом и baseline без него → грейдинг ассершенов → HTML-вьюер для человека → правка. Исполняемое есть и работает: `scripts/quick_validate.py` (проверяет frontmatter по allowlist `name/description/license/allowed-tools/metadata/compatibility`), `scripts/run_loop.py` (оптимизация description через `claude -p`, сплит 60/40 train/test, 3 прогона на запрос — защита от оверфита), `aggregate_benchmark.py`, `package_skill.py`, `eval-viewer/generate_review.py`. Шаблонов документа нет — только JSON-схемы evals в `references/schemas.md`.

**superpowers writing-skills 6.2.0** — метод TDD для документации: сначала прогон БЕЗ скилла (записать дословные рационализации), потом минимальный скилл под конкретные провалы, потом закрытие лазеек. Главная ценность 6.2.0 — таблица «форма гайдлайна ↔ тип провала»: запреты работают только против нарушения дисциплины, а против «выход не той формы» они измеримо ХУЖЕ, чем позитивный рецепт (и хуже контроля без гайда вообще); плюс запрет на nuance-клаузы («не X, если не важно» ломает рабочую формулировку). Исполняемых валидаторов нет, только `render-graphs.js` для graphviz и `wc -w` как проверка бюджета. Шаблон структуры SKILL.md есть, чек-лист создания есть (RED/GREEN/REFACTOR + Quality Checks).

**claude-md-improver** — метод аудита, а не авторинга: найти все CLAUDE.md → оценить по 100 баллам (команды 20, архитектура 20, неочевидные паттерны 15, лаконичность 15, актуальность 15, исполнимость 15) → выдать отчёт → спросить разрешение → точечные правки диффом. Скриптов нет (единственная команда — `find`). Шаблоны CLAUDE.md по типам проектов есть в `references/templates.md`. Слабое место: рубрика заточена под «проектный CLAUDE.md с командами сборки», под глобальные правила поведения (наш случай) она почти не стреляет.

**plugin-dev skill-development** — метод из 6 шагов (примеры использования → план ресурсов → структура → написание → валидация → итерация). Ценность в механике, а не в теории: явные числовые бюджеты (1500–2000 слов тело, <3000 без references, <5000 максимум), требование императива и третьего лица, чек-лист из 4 блоков, каталог типовых ошибок с парами ❌/✅. Скриптов у самого скилла нет, но в соседних есть готовые: `hook-development/scripts/hook-linter.sh`, `agent-development/scripts/validate-agent.sh`, `plugin-settings/scripts/parse-frontmatter.sh`. `agents/skill-reviewer.md` — готовый формат приёмочного вердикта (severity critical/major/minor + word count + оценка progressive disclosure).

**hookify writing-rules** — просто справочник по формату hookify-правил (frontmatter, regex, события bash/file/stop/prompt). К нашей задаче отношения не имеет; единственное переиспользуемое — правило нейминга «имя правила начинается с глагола: warn/prevent/block/require/check».

## 3. Есть ли готовый под нашу задачу?

**ЧАСТИЧНО — готового нет, но 80% материала уже лежит локально.** Каждый найденный скилл покрывает ровно ОДИН жанр: skill-creator и writing-skills — только SKILL.md, claude-md-improver — только CLAUDE.md, hookify — только свой DSL, doc-coauthoring и documentation-writer — человеческие доки. Ни один не покрывает спеки и проектные доки для агентов, ни один не даёт единого чек-листа «перед сохранением любого md», и ни у кого нет маршрутизации «этот файл такого-то жанра → вот его лимиты и обязательные секции». Плюс два кандидата прямо конфликтуют: superpowers требует в `description` ТОЛЬКО условия срабатывания без описания процесса, skill-creator и plugin-dev — наоборот, «что делает + когда». Выбирать между ними придётся самому — готовый скилл этот конфликт за нас не решает.

## 4. Что взять, если делаем свой

- **superpowers 6.2.0** (`.../superpowers/6.2.0/skills/writing-skills/SKILL.md`): таблица Match the Form to the Failure целиком; правило «description = только Use when, без пересказа workflow» с обоснованием; бюджеты слов (<150 / <200 / <500); запрет `@`-ссылок (форс-загрузка жжёт контекст); анти-паттерны (нарратив, мультиязычные примеры, код во флоучартах); Micro-Test Wording как процедура проверки формулировки.
- **anthropic-best-practices.md** (там же, `anthropic-best-practices.md`): «степени свободы» (узкий мост vs открытое поле) — лучший найденный критерий, насколько жёстко писать инструкцию; правило «ссылки на файлы ровно на один уровень вглубь»; ToC для файлов >100 строк; секция «Old patterns» вместо дат в тексте; финальный чек-лист (3 блока).
- **skill-creator** (`.../skill-creator/scripts/`): `quick_validate.py` — готовый валидатор frontmatter, расширяется под наши жанры за полчаса; `run_loop.py` — метод оптимизации description с train/test сплитом; `references/schemas.md` — схемы для evals.
- **plugin-dev** (`.../plugin-dev/unknown/skills/skill-development/SKILL.md` + `agents/skill-reviewer.md`): числовые бюджеты, Validation Checklist, формат вердикта ревьюера (severity + word count) — прямо ложится на наш «один проход качества».
- **claude-md-improver** (`.../claude-md-improver/references/quality-criteria.md`): 100-балльная рубрика и список red flags (мёртвые команды, ссылки на удалённые файлы, дубли между файлами) — как гейт актуальности.
- **doc-coauthoring** (anthropics/skills): reader-test — отдать готовый md свежему агенту без контекста и посмотреть, сможет ли он выполнить задачу. Дешёвая механическая проверка, подходит и для спек, и для CLAUDE.md.

## 5. Дыра — чего нет ни у кого

1. **Единый роутер по жанрам.** Нигде нет таблицы «SKILL.md / CLAUDE.md / rules/*.md / спека / доки проекта / task packet → свои лимиты, обязательные секции, тон, момент загрузки в контекст». Каждый скилл живёт в своём жанре и молчит про остальные.
2. **Спеки и проектные доки не покрыты вообще.** Ни у кого нет требований к спеке, по которой должен сработать имплементер-агент: критерии приёмки, точные пути файлов, DoD исполняемыми командами. При этом у владельца это основной рабочий жанр (`~/Documents/specs/`, карточки фабрики).
3. **Нет исполняемого пре-сейв гейта для не-SKILL.md.** `quick_validate.py` умеет только frontmatter SKILL.md. Ничто не проверяет CLAUDE.md и rules/*.md на длину, битые пути, дубли между файлами, конфликтующие правила.
4. **Нет правил дедупликации между слоями памяти.** CLAUDE.md vs rules/ vs skills/ vs vault vs auto-memory — где чему место и что делать, когда правило есть в двух местах. Для нашей среды это ежедневная боль.
5. **Ничего про многоязычие и про читателя-субагента.** Ни один кандидат не обсуждает «русский текст + английские термины» и не различает документ, который читает главный цикл, и документ, который читает субагент с чистым контекстом.
6. **Нет жизненного цикла.** Как понять, что md протух, кто и когда его перечитывает, как удалять устаревшее. Есть только «red flags» у claude-md-improver, и то как разовый аудит.
