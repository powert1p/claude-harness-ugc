# research — одно решение, глубина по неизвестному

Ресёрч обслуживает решение, не тему. Формулировка владельца — симптом; предложенный им инструмент («может, vector DB?») — гипотеза, пока он не сделал её требованием. На выходе «что берём» с доказательством, не обзор.

## Такт 0 — решение и что уже есть (без web)

- Какое решение принимается по итогам и что для него важно (скорость, деньги, встройка в стек) — из контекста, не спрашивая. Незаданные оси (объёмы, частота, лимиты) остаются неизвестными, выдуманное значение не подставляется и кандидаты по нему не отсеиваются.
- **Repo fit первым:** код и зависимости проекта, `~/.claude`, `ls -d ~/.<кандидат>`, прошлые `docs/research/*`. Актуальная реализация или прошлый ресёрч закрывает нужду → этап закрывается **одной строкой в чат**: «закрыл repo fit-ом: <файл/версия> · чего не хватает: …». Вход в ресёрч принудительный (brainstorming), а глубину выбирает скилл — эта строка и есть цена короткого пути: молчаливый пропуск = срыв 07.08. Знакомое название и похожий happy path fit не доказывают: нужны применимость, версия и отсутствие решающего пробела.

## Такт 1 — разведка, потом поисковое ТЗ, потом регистр

Форма поиска выбирается ПОСЛЕ разведки: регистр, взятый до первого запроса, фиксирует форму раньше, чем известна местность, и scout-ы уходят со словами оркестратора вместо слов рынка.

- **Разведка:** 2–3 коротких запроса за терминами, классами решений и готовыми подходами; ключевые источники открыть, рейтинг не строить. Свежая карта в контексте заменяет разведку; ясный lookup («как зовётся параметр таймаута в Reader 2.1») идёт сразу к источнику.
- **Поисковое ТЗ** 6–10 строк, в чат статусом, без approval: результат · контекст · ограничения отдельно от допущений · гипотезы и чем каждую опровергнуть · решающие неизвестные · условие достаточности. Шаблон и пример — `references/method.md`. Уточняется при фактах, меняющих решение, не после каждой выдачи. Приватный контекст в публичную строку не уходит — только обезличенные capabilities.
- **Регистр по ТЗ** (сомнение между двумя → легче); это намерения на входе в один процесс, не коридоры: concept проверяет готовую реализацию, если она нужна, tool пользуется концептами для поиска.

| Регистр | Признак | Ход |
|---|---|---|
| **concept** | «как это делают», новое в продукте, нужны паттерны | один scout |
| **tool** | нужен устанавливаемый артефакт: библиотека, скилл, MCP, сервис | 1–2 scout-а по реестрам |
| **funnel** | классов решений несколько, нужда составная | карта → глубина → вердикт/стек |
| **map** | владелец явно просит обзор, артефакта на установку нет | ширина воронки → файл-карта |

## Общие правила всех регистров

- Ищет Agent `scout`; несколько — одним сообщением, потолок 3. Scout read-only: его отчёт с секцией «Сырьё» сохраняет оркестратор в `docs/research/<дата>-<slug>.md` (legacy-проект с живым `.flow/` — `.flow/slices/<id>/research.md`), себе берёт дистиллят; пути из отчётов проверяются `ls`. 29.09 три scout-а получили «пиши сырьё в файл» и вернули «Write нет» — сырьё терялось.
- Каналы добычи — таблица «Каналы» в `~/.claude/agents/scout.md`, одно место; оркестратор без scout ищет по строке «Ресёрч» CLAUDE.md. Языки: английский — дефолт; русский — локальный рынок/1С/amoCRM/Хабр; китайский — отдельным проходом. Смешение языков в одном проходе роняет точность на 16–22 п.п. (arXiv 2606.15345) — второй язык только отдельным scout-ом.
- **Грейды свидетельств** у каждого утверждения о кандидате: *найдено* · *по докам* · *прогнано* · *вывод* · *неизвестно*. Snippet и сводка WebSearch/WebFetch (пересказ другой модели) — указатель, источник открывается; цифра в выводе — с дословной цитатой первоисточника (регулятор, вендор, доки), иначе *не подтверждено*; копии одной статьи — один источник; «docs v3» не доказывает лимит v2; конфликт версий — обе с пробой, а без пробы — неизвестно.
- **«Способов нет» запрещено:** ответ содержит ближайшие найденные концепты/доноры + секцию `Не нашёл (проверено): каналы, запросы`. Timeout/403/login и пустая успешная выдача — разные результаты, упавший канал называется вслух.
- **Стоп по сходимости:** два подряд поиска вернули то же → заход исчерпан; новый запрос меняет ЦЕЛЬ, не слова (переформулировка того же — предиктор провала, arXiv 2608.01913). Капы кругов — backstop. Стоп раньше капа, когда оставшиеся вопросы не меняют выбор; подтверждающие запросы ради сходимости не нужны.
- **Реестр непроверенного:** рядом с «Не нашёл (проверено)» — строка «Непроверенным осталось: …» (или «ничего»); незакрытый констрейнт без неё читается как проверенный (Illusory Completion).
- **Право нити:** запросы оркестратора — точки входа, не шопинг-лист; многообещающее сбоку тянется в том же прогоне, строка в сырьё почему. Scout возвращает «вскрывшиеся нити» со статусом подтверждена / опровергнута / новая; второй нырок — только в нить со свидетельством и вдвое уже.

## Регистры

**concept** — подсказки, не инструменты. Живость концепта = свежесть и авторитет источника. Один scout: 3–5 референсов «как это решают живые продукты», паттерны, анти-паттерны, «что берём / чего не берём»; ищется ПАТТЕРН, не отрасль. Инструментальная нужда всплыла → отдельный заход tool-регистром. Дистиллят: Проблема · находки «источник · концепт · что берём» · паттерны · Не нашёл (проверено).

**tool** — найти готовое, не собрать своё. «По мотивам» запрещено: нашёл живое — внедряй; своё — только после вердикта Build. Нужда — списком умений и ограничений, не темой. Искать где решения живут: реестры (npm/PyPI), каталоги скиллов, MCP-серверы, GitHub code search; статьи — потом. Живость: коммит ≤6 мес, разрешительная лицензия, видимое использование, доки — **сигналы для проверки, не порог**: зрелая либа с зелёным регресс-прогоном на нашем входе проходит, мёртвая с красивым README — нет.

**funnel** — мутная или составная нужда. Ширина: оси из классов решений ТЗ, по оси на scout, до трёх одним сообщением, запросы ≤5 слов, сырьё каждой оси оркестратор кладёт в `<дата>-<slug>-<ось>.md`; карта 5–8 вариантов строкой; глубина на ширине запрещена; структуру темы подсматривать в найденном. Развилка по карте: конкурируют → 2–3 кандидата в глубину из разных классов; закрывают разные куски → композиция: слои из карты, 2–3 кандидата на слой, «физически не стыкуется» раньше «нам не подходит», зрелость слоя решает Adopt/Build; слоёв больше четырёх → нужда не одна, разнести. Глубина: 1–2 scout-а, вход = цель + выводы ширины; после композиции один scout на все слои разом, заодно проверить готовое на несколько слоёв — оно бьёт сборку. Бюджет: два круга; карта врала → один возврат половинной шириной.

**map** — обзор без установки, только по явному слову. Ширина воронки, сведение — файл-карта в `docs/research/`: 5–8 игроков/классов, чем отличаются, «что это значит для нас». Глубины и цитатного аппарата нет намеренно; капа два круга.

## Вердикт — проба до Adopt

- **Adopt** (как есть) / **Extend** (основа + тонкая обёртка; обёртка толще чужого кода = Build под маской) / **Compose** (части в своих ролях) / **Build** (живого нет — при живых, но непригодных, назвать их непригодность и размер своей части). Решения сочетаются: Compose для целого, Adopt для парсера, Build для маппинга. Провал поиска, закрытый канал и незнание API Build не обосновывают.
- **Adopt и Extend — только после пробы:** минимальный решающий пример в доступной среде на своём формате/лимите, главном стыке или failure path, без mock проверяемого стыка; точное имя пакета и publisher сверены с реестром, угаданное не ставится. Прогнать нельзя → вердикт **условный**: «берём X при условии …, проба: <команда>» — законный исход, а не провал; непроверенный стык готовым не объявляется.
- **Compose:** capabilities без привязки к поставщику → часть на каждую; «Стыки» (вход/выход, runtime, поведение при ошибке, эксплуатация) и «Остаток» заполняются всегда, у каждого перехода владелец; проба выбирается та, что скорее опровергнет композицию; docs-совместимость и фактический end-to-end называются отдельно. Чек-лист — `references/method.md`.
- Формат: Решение · Нужда · Кандидаты с грейдами · ВЕРДИКТ · Проба (прогнана / условие) · Не подошло · Не нашёл (проверено) · Непроверенным осталось. Простой случай — абзац; составной — таблица capability → берём → свидетельство → стык/остаток.

## Перенос — найденное в свой путь (03.09)

Правило, выписанное из чужого флоу в свой файл, в работе не срабатывает: модель соглашается с текстом и делает иначе (arXiv 2605.01771), правило вне контекста в момент действия мертво. Сырьё: `docs/research/2026-09-03-transfer*.md` в cdp.

1. Донор целиком, своим файлом или кодом, с URL, коммитом и лицензией в шапке; вызов явный в шаге скилла, триггер тем же ходом; свежесть — скрипт diff с upstream.
2. До установки в путь — прогон на своём кейсе без донора и с ним: «ловит ли то, что ловит владелец». Не ловит → следующий слой — скрипт или кейс, не новое правило.
3. Вкус владельца переносится кейсами: каждое «не то» → артефакт + вердикт в `evals/` скилла.
4. Что считается — в скрипт; текст остаётся для несчитаемого.
5. Что не сработало — строкой в ledger с причиной, чтобы не вернулось вторым кругом.

## Правка этого скилла — только с evals

Изменение SKILL.md доказывается прогоном по `evals/README.md`: свежий evaluator получает только SKILL.md и `evals/cases.json` (для Такта 1 — `brief-cases.json`), решения до/после сравниваются по рубрике; «стало лучше» словами не принимается. Кейсы — вымышленные фикстуры, не факты о продуктах.

## Анти-паттерны

- ❌ Ресёрч пропущен молча — без строки «закрыл repo fit-ом»; регистр выбран до разведки.
- ❌ Adopt без пробы; первый живой кандидат = вердикт без карты (funnel/map); глубина на такте ширины.
- ❌ Выдуманное значение в незаданную ось; обзор вместо вердикта там, где просили решение.
- ❌ Concept-находки как разрешение не искать tool, когда нужен именно инструмент.
