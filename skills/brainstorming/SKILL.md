# /brainstorming — один вход, три пути

Владелец участвует в начале и на гейтах — между ними работа добивается без него, к нему приезжает готовое. Развилки, оставленные «на потом», всплывают на показах и превращают владельца в ОТК (aiplus 18–19.08).

**Церемония масштабируется с задачей; гейт — никогда.** Путь называется первой строкой ответа («M-задача: …»), владелец может поправить. Сомнение между путями → тяжелее. Скрытая сложность по ходу апгрейдит путь вслух; вниз пути не съезжают.

- **S** — диф в одно предложение: фикс, копейка, переименование, вопрос-проба. Сделать сразу, показать прогон. Без списка и гейта. Однострочный текст/отступ в UI — тоже S; UI-правка крупнее — Skill `design` (кадр до кода).
- **M** — scope ясен, подход очевиден. Понимание → короткое решение в чат: «беру X, потому что Y; жертвую Z» → ⛳ «го» → сделать одним заходом → прогон-доказательство (tsc, тесты, скрин) → статус.
- **L** — новая фича/модуль, мутный scope. Сессия → ТЗ → куски до прода, ниже.

Показал решение или блок — стоп до слова владельца; подача и старт работы в одном сообщении = пропущенный гейт. Перед работой M/L глянь, не идёт ли в репо параллельная сессия (`git log --oneline -5`, чужие свежие ветки) — пересечение назови и разведи.

## Список — витрина флоу (M/L)

Владелец читает работу через TodoWrite: он заводится первым действием; нет инструмента в сессии — список текстом в каждом сообщении. Этапы пунктами, «⛳ Твой ход — …» на остановках; активный этап развёрнут в шаги, закрытый схлопнут. Гейт уходит в `in_progress`, когда работа легла владельцу на стол, и закрывается ТОЛЬКО его словом. Врезка владельца по ходу → пункт в текущий этап или в конец, одной строкой сказать куда легла. Пункты отмечаются на границе шага, не пачкой в конце.

## Сессия L — текстом и кликами

Контекст собери сам до вопросов: CLAUDE.md проекта, код точечно, цифры — SQL с прода. Новое в продукте → Skill `research` ДО сессии. Разведка широкая и многофайловая → Agent `scout`, остальное сам.

1. **Тезис** — СВОЯ позиция из бизнеса владельца (деньги, сроки, данные, рынок): «строим X первым, потому что Y; против Z, потому что W» + порядок шагов и что каждый приносит. Тест: с тезисом можно не согласиться; спорить не с чем = пересказ, не показывается. Показ, целиком собранный из слов владельца, — зеркало (20.08); в каждом показе — вывод, которого владелец не говорил.
2. **Развилки — сначала профиль, потом вопрос.** До любого вопроса — профиль предпочтений: USER.md, vault `permanent/user-style/`, auto-memory; записанное предпочтение = дефолт, вопрос по нему не задаётся. Вопрос — не больше двух за сессию, только продуктовый (scope/UX/деньги), когда ветки дают материально разную работу и профиль молчит. Каждый вариант несёт три вещи: что изменится для юзера/бизнеса · что дальше по этой ветке (следующие шаги, цена) · рекомендация с причиной первой; дефолт при молчании — строкой. Вопрос без этого — «иллюзия выбора» (02.09: «примитивные, без контекста, сам догадываюсь, к чему приведёт ветка»). Гейт «го?» — строкой в тексте, не AskUserQuestion. Вкусовые дизайн-развилки — 2–3 варианта картинками живых продуктов (единственное место картинки). Ответ владельца на развилку → тем же ходом строка в USER.md с датой — иначе ответы не копятся (профиль стоял с 07.08).
3. **Дефолты** — списком «взял сам: … — по <USER.md дата / код / данные>», владелец правит только неверное; ожидания не требуют.
4. **Границы** — чего НЕ делаем, критерии «готово» языком продукта.

Одно слово владельца закрывает один блок; склейка всего под одно «ок» = срыв 20.08. Вопросы-оценки своей работы («верно понял?», «то ли это?») запрещены — подача утверждением или развилкой. Перед финалом — экспресс-чек Agent `architect` (самодостаточный пакет, формат в его description), правки впитать до показа.

**⛳ Гейт сессии:** владелец закрыл блоки. После — ТЗ-файл `docs/specs/<дата>-<slug>.md` из решений сессии (MUST-действия, чего НЕ делаем, decision log): он для машины, владелец его не читает. К ТЗ — план кусков: кусок = результат, проверяемый прогоном, одна страница/модуль за итерацию.

## Исполнение до прода — после «ок» владелец не нужен

Оркестратор раздаёт задачи и сверяет результат; сам пишет только S-правки. Каждая задача плана несёт файлы, точные изменения и DoD-прогон — самодостаточным пакетом (лимит — Skill `writing-md`): им живёт implementer, не ссылками на сессию.

- **Параллель:** независимые задачи → 2–3 Agent `implementer` одним сообщением; трогают одни файлы → `isolation: worktree`. Код про деньги, миграции и SQL-расчёты → implementer с `model: opus`.
- **Ledger:** `docs/specs/<slug>-progress.md` — строка на задачу: статус · evidence прогона. Обновляется на границе задачи; после потери контекста работа продолжается по ledger, не по памяти.
- Всё UI — по Skill `design`: путь на борде утверждён до кода, сборка сверяется с кадром; у фичи с UI модель данных, API и схема тоже ждут «ок» борда.
- Задача закрыта = DoD-прогон показан: тест, tsc, SQL-инвариант, side-by-side скрин; изменённый стык прогоняется с реальными соседями — mock этого стыка задачу не закрывает; заглушка и «пока сойдёт» сделанным не считаются, тесты под ответ не правятся.

- Два красных захода на одном месте → Agent `architect` на переосмысление, третьего лобового нет.
- Вопрос по дороге → PushNotification + секция «Вопросы владельцу», работа идёт по соседнему куску. Стоп полный только: деструктив данных (DROP/DELETE/TRUNCATE — вопрос ВСЕГДА), деньги, публикация от имени владельца.
- Новая фича/модуль или риск-путь (auth, деньги, прод-данные, миграции, SQL-финрасчёты) → перед закрытием один blind-ревью дефолтным агентом против ТЗ: maker неполноту своей работы не видит.
- Правка владельца против утверждённого — стоп и возврат на уровень выше с первого раза; «стоп» слушается на ближайшей границе такта.

## Статус — на закрытии куска и на «что осталось / ухожу»

Первой строкой итог языком продукта (что изменилось для юзера/бизнеса), затем:

```
СТАТУС: <готово N из M> · <главный блокер или «блокеров нет»>
✅ <результат> — <доказательство>   ⚠️ <результат> — не проверено: <какой проверки нет>
☐ <не сделано — что нужно>          ⛔ <заблокировано — чем, кто разблокирует>
Дальше, по порядку: <первым — что разблокирует остальное>
```

Пункт — результат, не активность: «401 на истёкший токен», а не «поправил auth.go». Между ✅ и ⚠️ выбирается ⚠️. Вопрос владельцу — только с дефолтом («промолчишь — сделаю X»). Техметрики — одной строкой в конце. Затем Skill `wrap`.

## Анти-паттерны

- ❌ Вопрос, ответ на который лежит в коде/данных/мире или в профиле владельца; вопрос ради участия — без «что изменится» и «что дальше по ветке»; второй блок вопросов на S/M; текстовая простыня на утверждение — решения коротко и кликами, кадры только про UI.
- ❌ Даунгрейд пути ради скорости («слишком просто для гейта» — у M/L гейт всегда); работа M/L без списка или список задним числом под сделанное.
- ❌ Финиш на MVP: «готово» определяет прогон по критериям ТЗ, не «код собрался».
